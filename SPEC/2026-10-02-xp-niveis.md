## 2. Escopo

### 2.1 Fonte (visão §1, §4, §5 D7)

> **XP**: pontos de experiência concedidos por ações de aprendizagem (concluir aula, acertar questão, entregar avaliação). Não pode ser comprado nem transferido.
>
> **Nível**: faixa de progresso do estudante derivada de XP acumulado. Subir de nível é irreversível.
>
> **D7 — Gamificação: XP e níveis.** Escopo: concessão de XP por ações e tradução de XP em níveis. Entidades: regra de XP, evento de XP, saldo de XP, faixa de nível. Regras: XP é concedido apenas por ações verificadas; configuração de XP é ajustável por escopo (global do professor/admin); nível é monotônico (nunca diminui); XP total e XP do período são métricas distintas.

Fluxo (visão §4): passo 4 "marca como concluída; recebe XP"; passo 5 "recebe feedback e XP imediato por acerto"; passo 6 "resultado … pode conceder XP/recompensa"; passo 8 "XP acumulado eleva o nível". Regra de ouro: "toda recompensa (XP, nível, …) é calculada pelo servidor a partir de ações verificadas; o cliente apenas exibe".

## 3. Fluxos

### 3.1 Estudante — ganhar XP (passos 4–6, 8)

1. Conclui uma aula (F2-14), acerta uma questão de exercício (F3-06) ou envia uma tentativa de avaliação (F3-12).
2. Na **mesma transação** da ação, o servidor verifica se ela é elegível (R-X2–R-X5), calcula o valor pela configuração efetiva do curso (R-X7) e grava um **evento de XP** (§5.2) e o **saldo** atualizado (§5.3).
3. A resposta da ação passa a trazer `xp: {ganho, total, nivel, subiuNivel}` (§6.3). Ação não elegível (repetição, erro, dissertativa) → `ganho: 0`.
4. Quando o professor termina de corrigir uma tentativa de avaliação (F3-15) e a nota supera a maior nota já remunerada, o XP de nota é concedido ao **estudante** (R-X5); a resposta de F3-15 (professor) não muda.
5. O estudante consulta seu XP e nível (F5-01); o perfil (F1 rota 7) passa a exibir `nivel`.

### 3.2 Administrador — valores globais (T5.4)

1. Lê (F5-02) e altera (F5-03) os quatro parâmetros globais (§4.1 R-X6). A alteração vale para ações **posteriores** (R-X8).

### 3.3 Professor — ajuste por curso (T5.4)

1. Professor dono (ou admin) lê (F5-04) a configuração do curso: valor global, ajuste do curso (ou `null`) e valor efetivo de cada parâmetro.
2. Altera (F5-05) um ou mais ajustes dentro de 0–2× o global; `null` remove o ajuste (volta ao global).

**Contrafluxos:** `401` sem sessão; `404` curso inexistente ou não visível; `403` papel/titularidade; `400` corpo inválido.

## 4. Regras

### 4.1 Concessão

| ID | Regra | Natureza / detalhe | Rastreabilidade |
|---|---|---|---|
| R-X1 | **XP só no servidor, só por ação verificada** | **Herdada.** Os únicos gatilhos são os quatro de R-X2–R-X5, executados dentro das rotas F2-14, F3-06, F3-12 e F3-15. Nenhuma rota aceita XP, nível ou valor de evento vindo do cliente; não existe rota que crie, transfira ou compre XP | visão §1, §4 regra de ouro, §5 D7 |
| R-X2 | **Concluir aula** | **Decisão U-1.** Primeira conclusão de `(estudante, aula)` (F2-14 com `201`) concede `xp_conclusao_aula` (padrão 10). Repetição (`200`, D6 R-D6-2) → `ganho: 0` | visão §1, §4 passo 4; D6 R-D6-2 |
| R-X3 | **Acertar questão de exercício** | **Decisão U-2 (resolve P-24).** Tentativa de D4 com `acerto = true` concede `xp_acerto_questao` (padrão 5) **somente se** for o primeiro acerto do estudante naquela questão — vale em qualquer tentativa (errar antes não reduz). Acertos seguintes, erros e dissertativas (`acerto = null`, P-25) → `ganho: 0` | visão §4 passo 5; D4 R-Q6/R-Q8/R-Q9 |
| R-X4 | **Entregar avaliação** | **Decisão U-3.** A **primeira** tentativa do estudante numa avaliação (F3-12 com `201`), qualquer que seja o status, concede `xp_entrega_avaliacao` (padrão 20). Tentativas seguintes → 0 | visão §1, §4 passo 6 |
| R-X5 | **Melhoria da nota de avaliação** | **Decisão U-3 (resolve P-34 — parcela XP).** Sempre que uma tentativa passa a `corrigida` (em F3-12 sem dissertativa, ou em F3-15 ao completar ou recorrigir a correção), seja `M` a maior nota já **remunerada** do estudante na avaliação (0 se nenhuma) e `N` a nota da tentativa. Se `N > M`: concede `round(k × N) − round(k × M)`, com `k = xp_por_ponto_nota` (padrão 3) e arredondamento meio para cima; `N` passa a ser a nova maior remunerada. Se `N ≤ M` → 0. Com `k` constante, o total recebido por avaliação é `round(k × maior nota)` ≤ `10k` (padrão: 30) | visão §4 passo 6; D5 R-A8/R-A9/R-A10 |
| R-X6 | **Questão de avaliação não paga por acerto** | **Decisão U-2.** Respostas de avaliação (`resposta_avaliacao`) nunca disparam R-X3; o desempenho na avaliação é remunerado só por R-X5 | decisão do usuário |
| R-X7 | **Idempotência garantida pelo banco** | **Proposta D7-a.** Cada evento tem uma `chave` única (§5.2): `aula:{aulaId}`, `acerto:{questaoId}`, `entrega:{avaliacaoId}`, `nota:{avaliacaoId}:{N em centésimos}` (sempre junto do `usuario_id`). Corrida entre dois envios simultâneos → no máximo um evento por chave; o perdedor recebe `ganho: 0` sem erro. Eventos com valor efetivo 0 (configuração 0) **também são gravados**, para que a ação não pague depois se a configuração subir | visão §5 D7 ("evento de XP"); D6 R-D6-2 (corrida) |
| R-X8 | **Atomicidade** | **Proposta D7-b.** Ação, evento e saldo são gravados na mesma transação; falha em qualquer um desfaz a ação inteira. Nunca existe ação registrada sem o XP correspondente, nem XP sem ação | visão §4 regra de ouro |
| R-X9 | **Só estudante ganha XP** | **Derivação.** As quatro ações de origem já são restritas ao papel estudante (D3 R-15, D4 R-Q11, D5 R-A12); F3-15 credita o **dono da tentativa**, nunca o professor | visão §3 P1 |

### 4.3 Saldo, nível e período

| ID | Regra | Natureza / detalhe | Rastreabilidade |
|---|---|---|---|
| R-X15 | **XP total** | **Herdada + U-7.** `xpTotal = Σ xp` dos eventos do estudante. Eventos são **somente inclusão**: nunca editados nem apagados (exceto pela exclusão da própria conta, §5) | visão §5 D7 |
| R-X16 | **Fórmula de nível** | **Decisão U-4.** XP necessário para alcançar o nível `n` (n ≥ 1): `L(n) = 50 × n × (n − 1)` — nível 1 = 0, 2 = 100, 3 = 300, 4 = 600, 5 = 1.000, 10 = 4.500. `nivelDe(xp)` = maior `n` com `L(n) ≤ xp`, calculado com **aritmética inteira** (sem ponto flutuante, Proposta D7-e). Sem teto. **Não configurável** | visão §1 ("faixa de progresso derivada de XP") |
| R-X17 | **Nível monotônico** | **Herdada + U-4.** O saldo guarda `nivel = max(nivel gravado, nivelDe(xpTotal))`. Como XP nunca diminui (R-X15, U-7) e a curva é fixa, isso já vale por construção; o máximo é uma garantia extra | visão §1 ("subir de nível é irreversível"), §5 D7; `PLAN.md` §4 princípio 8 |
| R-X18 | **XP da semana** | **Decisão U-5.** `xpSemana = Σ xp` dos eventos com `concedido_em` na semana ISO corrente (segunda 00:00 até domingo 23:59:59.999 em `America/Sao_Paulo`). Calculado na leitura, sem contador zerado periodicamente | visão §1 ("XP semanal"), §5 D7 ("XP total e XP do período são métricas distintas") |
| R-X19 | **Conta sem eventos** | **Derivação.** Estudante sem eventos: `xpTotal = 0`, `xpSemana = 0`, `nivel = 1` (saldo pode não existir ainda — criado no primeiro evento) | R-X16 |
| R-X20 | **Exclusão de conteúdo não remove XP** | **Decisão U-7 (resolve P-16 — parcela gamificação).** Eventos guardam `referencia_id` e `curso_id` **sem FK**; excluir aula, questão, avaliação, módulo ou curso não afeta eventos nem saldo. Consequência: se o conteúdo for recriado, é outro id e pode pagar de novo (Proposta D7-f) | visão §1 (nível irreversível) |
| R-X21 | **Edição de gabarito e recorreção** | **Derivação** de D4-g/D5-j/D5-h. `acerto` e `nota` são instantâneos; XP segue o mesmo princípio. Recorreção que **baixa** a nota não retira XP; recorreção que **sobe** acima da maior remunerada paga a diferença (R-X5) | D4 R-Q6; D5 R-A9/R-A13 |
| R-X22 | **Sem retroatividade para ações anteriores a F5** | **Proposta D7-g.** Conclusões, acertos e tentativas registrados antes da implantação de T5.2 **não** geram eventos. Backfill → P-46 | — |

## 5. Modelo físico (exercício de P-08 para D7)

Convenções da técnica §2.2.1/§2.2.2. A **faixa de nível** da visão não vira tabela: é a função fixa de R-X16 (Proposta D7-e).

### 5.1 `config_xp_global` (regra de XP — escopo global)

| Dado | Tipo/restrição |
|---|---|
| `id` | UUID PK — **linha única** (criada na migração com os padrões) |
| `xp_conclusao_aula` | INTEGER NOT NULL (0–1.000) DEFAULT 10 |
| `xp_acerto_questao` | INTEGER NOT NULL (0–1.000) DEFAULT 5 |
| `xp_entrega_avaliacao` | INTEGER NOT NULL (0–1.000) DEFAULT 20 |
| `xp_por_ponto_nota` | INTEGER NOT NULL (0–1.000) DEFAULT 3 |
| `criado_em` / `atualizado_em` | TIMESTAMP |

### 5.2 `config_xp_curso` (regra de XP — escopo do curso)

| Dado | Tipo/restrição |
|---|---|
| `curso_id` | UUID PK, FK → `curso.id` (CASCADE) |
| `xp_conclusao_aula` / `xp_acerto_questao` / `xp_entrega_avaliacao` / `xp_por_ponto_nota` | INTEGER NULL (≥ 0; teto 2× global validado na aplicação, R-X12) |
| `criado_em` / `atualizado_em` | TIMESTAMP |

### 5.3 `evento_xp` (evento de XP)

| Dado | Tipo/restrição |
|---|---|
| `id` | UUID PK |
| `usuario_id` | FK → `usuario.id` (CASCADE) |
| `origem` | ENUM(`conclusao_aula`, `acerto_questao`, `entrega_avaliacao`, `nota_avaliacao`) NOT NULL |
| `referencia_id` | UUID NOT NULL — aula, questão ou avaliação; **sem FK** (R-X20) |
| `curso_id` | UUID NOT NULL — **sem FK** (R-X20); insumo para rankings por curso (D11) |
| `chave` | TEXT NOT NULL; UNIQUE (`usuario_id`, `chave`) (R-X7) |
| `xp` | INTEGER NOT NULL (≥ 0) |
| `nota_referencia` | NUMERIC(4,2) NULL — só em `nota_avaliacao`: a nova maior nota remunerada `N` |
| `concedido_em` | TIMESTAMP NOT NULL; INDEX (`usuario_id`, `concedido_em`) |
| `criado_em` / `atualizado_em` | TIMESTAMP |

A maior nota remunerada `M` (R-X5) é `MAX(nota_referencia)` dos eventos `nota_avaliacao` de `(usuario, avaliação)`.

### 5.4 `saldo_xp` (saldo de XP)

| Dado | Tipo/restrição |
|---|---|
| `usuario_id` | UUID PK, FK → `usuario.id` (CASCADE) |
| `xp_total` | INTEGER NOT NULL (≥ 0) — igual a `Σ evento_xp.xp` (invariante testada) |
| `nivel` | INTEGER NOT NULL (≥ 1) — máximo atingido (R-X17) |
| `criado_em` / `atualizado_em` | TIMESTAMP |

O saldo é atualizado com `xp_total = xp_total + :xp` (incremento no banco, não leitura-e-escrita) dentro da transação de R-X8.
